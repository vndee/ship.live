# Service Health

Approved direction: public HTTP APIs, configured through the dashboard UI. Team health data, independent from GitHub activity. Service Health is a separate navigation tab with its own expiring read-only share links; existing dashboard links cannot read health data.

Services group one or more named probes. Each probe has URL, GET/HEAD method, optional secret headers, interval (30–3600 seconds), timeout (1–20 seconds, below interval), accepted status range, optional max latency, optional JSON path equality condition, failure/recovery thresholds (1–10), and enabled state. Defaults: GET, 60s, 10s, 200–299, 3 failures, 2 successes. No arbitrary code or regex execution. Empty headers on edit preserve existing secrets; explicit removal supported.

Public probes must reject private, loopback, link-local, multicast and reserved IPs, including DNS responses and IPv4-mapped IPv6. Resolve before each request, pin the validated address, preserve TLS hostname verification, never follow redirects. Bound DNS/request duration and response bytes; never save response bodies or echo credentials/errors containing URLs. Encrypt secret headers at rest using TOKEN_ENCRYPTION_KEY and probe identity as AAD.

PostgreSQL stores services, probe definitions, latest status, durable schedule and result history (at least 30 days). A worker claims due probes with expiring leases and SKIP LOCKED, executes with bounded concurrency outside transactions, and accepts results only for the current definition/lease. Pause/edit/delete invalidate pending results. Failures before threshold show degraded; down recovers only after configured consecutive successes. Never checked or overdue results show unknown. Uptime is explicitly the percentage of successful recorded checks over the last 24 hours, not time-weighted availability; missing checks do not count as successes.

Authenticated team members can view/configure team probes. Validate current team GitHub installation access, original session and database membership for requests. Mutations require existing same-origin CSRF protections. A separate health SSE channel sends invalidations; cached snapshots load independently from GitHub feed. Changing measurement rules or credentials starts a new history series; label and pause/resume edits preserve existing history and recovery thresholds. Health share links use a separate token namespace and expose an explicit allowlist of service/probe names, statuses, latency and history. URLs, headers and conditions stay private. Shares include current and future services for the team. Create/copy/expire/rotate/revoke follow dashboard mechanics with immediate SSE invalidation and creator access revalidation. No new public configuration API tokens. Browser uses session-authenticated JSON routes.

UI: Service Health tab in team navigation; service summary, status badges, latency, last check, 24-hour check success rate, recent results and state-change timeline. Configuration form supports create/edit services and multiple probes, pause/resume, queued check now and delete. First snapshot causes no alerts; down/recovery transitions highlight and announce accessibly, respecting reduced motion. Health must not award engineering XP.

Validation: unit tests for definition validation, condition evaluation, state thresholds and SSRF; database tests for tenancy, leases, stale result fencing, retention and secret redaction; route tests for auth/CSRF; typecheck/build/format and browser UI checks. Do not deploy or push this feature until requested.
